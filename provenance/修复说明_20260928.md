# 三项审计问题的修复

详细口径见 [复现与比较契约](REPRODUCIBILITY_CONTRACT.md)，机器可读结果见
[证据汇总](evidence_20260928/SUMMARY.json)。本文的 EXP-001/002 是此次评审问题编号，
不复用早期实验注册表中同名编号的实验定义。

| 问题 | 本次修复 | 仍保留的边界 |
|---|---|---|
| EXP-001：冻结运行与发布版本对应 | 原始 pin、保留文件、发布文件的散列映射；逐例 archive、原始 receipt、实际命令与历史环境记录；发布基准 commit | 历史运行 commit 未记录；未重建全部历史环境，原始大包未随 Git 分发，完整软件复现链仍未闭合 |
| EXP-002：比较器契约 | 九种所记录配置的版本证据、dtype、恢复字段、完整收费对象、命令和恢复记录；保留 CSR_BZIP2 两例失败与修复尝试 | 结论限于所记录配置及已暴露面板，不据此强化公平性、普遍优越性或跨会话速度排名 |
| E3：缺失依赖与成员身份 | 补回原始 VALUE_BEST_OF_9_50_005/worker.py 和 PINS.json；核对实际 manifest、成员散列和模型尺寸；检查全部 50 个 QSH1 header；用发布源码验证代表样本五个 arm 的独立进程解码 | no_sharing 只指已确认的 singleton 概率替换；K32 tail/条件表、B8 support 共享及共享中心 header 均仍保留 |

归档核验覆盖 1,000 个 K32 结果、9,000 条比较器结果，以及 E3 五个 arm 的
250 个包。历史恢复 receipt 与本次新增的五个代表性解码检查分开记录；没有重新编码
整个队列，也没有改写原实验目录。比较器计费文件按实际字节长度核对，不将工作文件
混入收费对象，也不漏掉 manifest、metadata、permutation 或容器开销。

`receipts.zip` 按 SHA256 保存原始 JSON 字节；逐例 JSONL 提供查找入口。
`COMPARATOR_CONTRACTS.json` 汇总实际观察到的 dtype、manifest 配置、运行环境版本与
收费文件布局。缺失的历史环境字段保持缺失，当前环境不反填为历史事实。

旧 E3 汇总中“八类 tail”的错误已更正为实测 B8/K32；原说明保留在
`docs/historical/E3_CONSOLIDATED_README.md`，其原始 SHA256 仍受源码清单校验。

本地验证入口：

```text
python tools/verify_evidence_bridge.py
python tools/test_evidence_bridge.py
python tools/check_release.py
```

`verify_evidence_bridge.py` 只需公开证据包；`check_release.py` 还要求锁定的
打包环境。前者通过不意味着本机重新恢复了整个历史实验队列。
